- Диагностика: сервер сохранял полный initData в /tmp/miniapp_initdata_last.txt (только на время отладки). В initData Дмитрия (573 симв.) обнаружилось поле **signature** — новый формат Telegram Mini Apps 2025+.
- 🔑 КОРЕНЬ ПРОБЛЕМЫ: я считал secret_key = HMAC_SHA256(key=bot_token, msg="WebAppData"), а по документации Telegram правильно: **secret_key = HMAC_SHA256(key="WebAppData", msg=bot_token)**. Мой самогенерированный тест проходил, потому что считал hash тем же (неправильным) способом — самосогласованный тест НЕ доказывает корректность. Реальный initData прошёл ТОЛЬКО при правильном порядке (анализ: ✅ excl_sig=False decode=True swap=True).
- Дополнительно: data_check_string включает ВСЕ поля кроме hash (включая signature), значения URL-декодированы (parse_qsl), сортировка по ключу.
- Фикс: auth.py verify_init_data переписан на стандартный алгоритм. Проверено: verify OK + login OK на реальном initData Дмитрия; POST /api/auth через HTTP → 200 + токен.
- ⚠️ УРОК: при проверке подписей/хешей использовать ТОЛЬКО реальные данные (или независимый эталон), самогенерированные тесты могут быть самосогласованно-ошибочными.
- Временные файлы диагностики удалены (initData — чувствительные данные).

## 15:34 — FaceID принимает лицо, но вход блокировался (глюк isAuthenticated на iOS)
- Скриншот Дмитрия: FaceID системный диалог РАБОТАЕТ и принимает лицо, но под кнопкой «FaceID не пройден» (две плашки: authError + bioStatus).

- ⚠️ УРОК: на iOS Telegram WebView BiometricManager.isAuthenticated глючит — не делать его единственным критерием входа; callback authenticate = диалог отработал.
