**Диагностика (живьём, 11.09):** ошибки Oura различаются так:
- неверный client_secret → `401 invalid_client`
- JSON-тело вместо form-urlencoded → `400 {"status":400,"title":"Bad Request"}`
- нет `grant_type` → то же самое
- лишний/дублированный параметр (PKCE `code_verifier`, дубль `client_id`) → `400 invalid_request`

**Поправка к прежнему выводу:** `invalid_request` НЕ означает только malformed-запрос. Oura отдаёт его и на код, который не может принять (истёк/использован/неизвестен) — проверено на 4 кодах, включая старый реальный; клиент-аутентификация при этом проходит (иначе был бы 401). По одной этой ошибке форму запроса судить нельзя.

**Oura API факты:** token endpoint — параметры в теле, `application/x-www-form-urlencoded`, UTF-8; `client_id`/`client_secret` обязательны, если не HTTP Basic; refresh_token одноразовый (ротация); PKCE не поддерживается. Scopes: `personal, daily, heartrate, workout, session, spo2Daily` (SpO2 пишется именно `spo2Daily`). Серверный flow: approve → `GET redirect_uri?code=***&scope=…&state=…`.
