## A. Executive Summary

Архитектура в целом **здоровая и прагматичная**: ядро OpenClaw держит чистые abstraction boundaries (gateway / plugins / tools / memory / channels), скрипты решают реальные задачи без излишней сложности. Но система выросла органически: есть мёртвый код, дублирование ответственности, 2 venv, SQLite-БД с чувствительными данными в git, открытый наружу miniapp на 0.0.0.0:8080 и tool-плагины без таймаутов. Это «рабочая лошадка с накопленным техдолгом», а не «конструктор из коробки».

### 5 главных проблем
1. **Секреты/БД в git**: `miniapp.db` (users, sessions, audit_log), `ai-memory.db`, `data/app.db` лежат в репозитории. Пароли-хеши и токены сессий ушли в историю git. 🔴
2. **`.venv/` закоммичен**: 5615 файлов (~150MB, duckdb.so 60MB, numpy 25MB) в git → репо раздут до 92MB. `.gitignore` закрывает `venv/`, но не `.venv/`. 🔴
3. **miniapp на 0.0.0.0:8080** без TLS — доступен извне напрямую, защита только на уровне приложения. 🟠
4. **Дублирование и мёртвый код**: два мониторинга авиабилетов (flight_watch.py + flight_api.py), icloud_calendar.py (327 строк, календарь = Google), orchestrator.py (мёртвый после выпила iCloud), backup-crontab ссылается на удалённые скрипты. 🟠
5. **Tool-плагины без таймаутов**: tg-user-tools и jina-core используют fetch без AbortSignal → зависший HTTP-вызов вешает tool call агента навсегда. 🟠

### 5 сильных сторон
1. Секреты прод-конфига вынесены из git: openclaw.json (600) + credentials/ (600), .env вне git.
2. Плагины на официальном SDK (`definePluginEntry`), контракты tools объявлены, манифесты корректны — расширяемость честная.
3. healthcheck.sh + cron-прогон — реальный smoke-тест ключевых путей (gcal, digest, miniapp, telegram-user-svc) ежедневно.
4. Календарь на Google API с OAuth — правильное решение, аккуратная реализация (токены-рефреш, Europe/Moscow).
5. Троттлинг и retry на 429 в jina-core (батчи 20, backoff 20/40/60s) — уже учтён rate limit провайдера.

### Общий приоритет
**P0: вычистить секреты из git + починить .gitignore. P1: таймауты в плагинах. P2: закрыть miniapp (TLS/loopback). P3: удалить мёртвый код и дубли. P4: унификация venv, ротация логов.**

## C. Findings

### 1. Critical issues

**C1. Чувствительные данные в git-истории**
- Файлы: `miniapp/miniapp.db` (таблицы users: password_hash, sessions: token, audit_log), `ai-memory.db`, `data/app.db` — все в `git ls-files`.
- Почему: приватный репо, но история нестираема; при утечке/передаче репо — компрометация паролей и сессий.
- Последствие: реальный риск утечки PII и сессионных токенов.
- Исправление: `git rm --cached`, добавить `*.db` в .gitignore, ротация токенов miniapp (сбросить sessions), при необходимости — purge истории (filter-repo) или пересоздать репо.

**C2. `.venv/` закоммичен (5615 файлов)**
- `git ls-files | grep -c '^.venv/'` = 5615 из 6963; pack 87MB; duckdb.so 60MB.
- Почему: `.gitignore` исключает `venv/`, но не `.venv/`; venv создан как `.venv` (скрытая папка).
- Последствие: раздутый репо, медленный clone/push, мусор в истории.
- Исправление: `git rm -r --cached .venv`, добавить `.venv/` в .gitignore, push (история останется, но файлы уйдут).

**C3. miniapp слушает 0.0.0.0:8080**
- `ThreadingHTTPServer(("0.0.0.0", port))` — открыт на всех интерфейсах без TLS.
- Почему: auth на уровне приложения (initData HMAC + пароль), но трафик в открытом виде, DoS-вектор открыт.
- Последствие: перехват паролей/токенов в локальной сети, атаки снаружи.
- Исправление: bind 127.0.0.1 + nginx-реверс с TLS (как gbkz.uk) или хотя бы ufw-ограничение.

### 2. High priority

**H1. Tool-плагины без таймаутов**
- `tg-user-tools/index.js` и `jina-tools/jina-core.js`: `fetch()` без AbortSignal.
- Последствие: зависший бэкенд (Telegram svc, Jina) вешает tool call → агент ждёт вечно, токены горят.
- Исправление: `AbortSignal.timeout(ms)` на все fetch (10–30s), единый helper.

**H2. Дублирование мониторинга авиабилетов**
- `travel/flight_watch.py` (avticket.ru парсинг) и `travel/flight_api.py` (Travelpayouts API) — оба в cron 6:00/18:00, оба пишут свои state-файлы, оба шлют в TG.
- Последствие: дублирующие уведомления, два источника правды, двойной расход.
- Исправление: оставить flight_api.py (API надёжнее парсинга HTML), flight_watch.py удалить или перевести в fallback.

**H3. Мёртвый код**
- `calendar/icloud_calendar.py` (327 строк) — календарь = Google, iCloud-путь выпилен.
- `calendar/orchestrator.py` — `_collect_news` заглушка (TODO), после выпила iCloud не вызывается; MEMORY.md упоминает несуществующий `import icloud_calendar` — доки врут.
- `backup-crontab-20260820.txt` ссылается на `services/assistant_bot/morning_digest.py` и `memory_compactor.py` — папки не существует.
- Последствие: путаница, риск «оживления» старого пути.
- Исправление: удалить/в _trash_, обновить MEMORY.md.

**H4. memorySearch платный при наличии бесплатного**
- `agents.defaults.memorySearch` → openrouter text-embedding-3-small (платно). Теперь есть Jina embeddings в рамках 10M токенов.
- Исправление: переключить провайдера memorySearch на Jina (или оставить hybrid с Jina) — экономия.

**H5. bot_sender.py парсит openclaw.json руками**
- Читает botToken из структуры конфига (accounts.default.botToken / botToken / файловая ссылка) — хрупко, сломается при рефакторинге формата.
- Исправление: вынести токен в credentials-файл (как travelpayouts.key) или читать из /root/.openclaw/.env.

### 3. Medium priority

**M1. Два venv**: `.venv` (35 пакетов, в git) и `venv` (55 пакетов, в .gitignore) — дублирование, непонятно какой активный. Унифицировать в один + requirements.txt.

**M2. jina_rag.json кэш 10MB** содержит фрагменты MEMORY.md/memory в открытом виде на диске (chmod по умолчанию). Хранить в /root/.openclaw/cache (уже там, 700 у .openclaw — приемлемо), но добавить chmod 600 и очистку старых.

**M3. Застрявшая delivery**: `a4fc1e2a...` в состоянии `send_attempt_started` — recovery отказывается от воспроизведения без reconciliation. Сообщение потеряно навсегда. Нужен ручной разбор (delivery-queue) или сброс состояния.

**M4. healthcheck.sh устарел**: пишет «telegram-user-svc: не systemd-юнит, а ручной процесс» — а юнит существует и active. Не проверяет jina-плагин, git-чистоту, размер логов. Дополнить.

**M5. Логи cron без ротации**: healthcheck.log, flight_*.log растут бесконечно. Добавить logrotate или `>> log 2>&1` + `tail -100`/truncate.

**M6. Нет rate limiting на miniapp** — брутфорс пароля возможен (audit_log есть, но нет блокировки). Добавить задержку/лимит попыток.

**M7. 15 бэкапов openclaw.json** без ротации — оставить 3–5 последних, остальные в архив/удалить.

### 4. Low priority

**L1.** `tmp/cbc_en.py` — разовый скрипт в workspace (в git? tmp/ не в .gitignore — проверить; если да — добавить tmp/ в ignore).
**L2.** `__pycache__` в workspace — в .gitignore, ок, но можно чистить.
**L3.** `STATE.md` vs `MEMORY.md` дублируют друг друга — определить единый источник.
**L4.** `.gitignore` `*config*.json` — слишком широкий паттерн, может скрыть нужные конфиги.
**L5.** Нет CI/lint/тестов для скриптов (py_compile в healthcheck — минимум, но не тесты).

## D. Optimization Plan

1. **Убрать**: icloud_calendar.py, orchestrator.py, flight_watch.py, backup-crontab, tmp/cbc_en.py, дубли бэкапов.
2. **Упростить**: один venv + requirements.txt; один путь отправки TG (telegram-user-svc через tg-user-tools), bot_sender оставить как fallback.
3. **Кешировать**: digest (RSS/TG-посты по ETag/времени, чтобы не дёргать 2×/день одинаковое), jina-индекс (уже есть state-кеш — ок, но переиндексация при любом изменении памяти — добавить debounce/ручную переиндексацию).
4. **Lazy loading**: MCP-серверы (context7, github) уже стартуют по требованию npx — убедиться, что не грузятся при каждом старте гейтвея (сейчас грузятся — см. процессы); перевести в отложенный запуск.
5. **В отдельные сервисы**: miniapp (уже отдельный systemd — ок), telegram-user-svc (уже отдельный — ок). Больше ничего не требуется.
6. **Переписать**: bot_sender (чтение токена), healthcheck.sh (актуализировать), jina-core fetch-helper (таймауты).
7. **Где сократить токены**: memorySearch → Jina; digest — суммаризировать только отобранные посты (не все 3/канал); проверять длину контекста перед tool-вызовами.
8. **Где ускорить runtime**: AbortSignal на все fetch; flight_api вместо парсинга HTML; npx-серверы с предзагруженными модулями.

## F. Target Architecture

```
┌────────────────────────────────────────────────────────────┐
│                      OpenClaw Gateway                        │
│  (plugins: deepseek/openrouter/google/parallel/perplexity,   │
│   tg-user-tools, jina-tools, memory-core, telegram)          │
├──────────┬──────────┬──────────┬──────────────┬─────────────┤
│ Channels │  Tools   │  Memory  │   Providers  │    MCP      │
│ telegram │ (SDK)    │ search   │  LLM/Image   │ context7/   │
│          │ jina_*   │ hybrid   │  deepseek    │ github      │
│          │ tg_*     │ Jina RAG │  openrouter  │ (lazy)      │
└────┬─────┴────┬─────┴────┬─────┴──────┬───────┴──────┬──────┘
     │          │          │            │              │
  HTTP/WS    HTTP      SQLite      REST API        npx subproc
  (nginx     (nginx    ai-memory   deepseek/       (on-demand)
   TLS)      TLS)      .db         openrouter
     │          │
  miniapp    telegram-
  :8080→127  user-svc
  (loopback) :8765
```

- **Слои**: Gateway (оркестрация) → Plugin SDK (tools) → Services (systemd: miniapp, telegram-user-svc) → Storage (credentials, cache, DB).
- **Интерфейсы**: все внешние вызовы через единый http-helper с timeout/retry; секреты только через credentials-файлы, не через парсинг конфига.
- **Guardrails**: rate-limit на miniapp, таймауты на все fetch, лимит токенов на tool-вызовы (макс. размер ответа), проверка путей в jina_rag (запрет выхода за workspace).
- **Plugin lifecycle**: единый паттерн (manifest + SDK + контракты) уже есть; добавить: таймауты, изоляцию FS, логирование вызовов, метрики токенов на tool.
- **Queues**: для digest/доставки — пока не нужны (объём мал), но delivery-recovery требует ручного разбора застрявшей записи.

## G. Final Verdict

1. **Система рабочая и разумно спроектирована** для личного ассистента: ядро OpenClaw + тонкий слой кастомных скриптов/плагинов решают задачи без оверинжиниринга.
2. **P0 — git-гигиена**: убрать из репо `.venv/` и `*.db` (секреты!), починить .gitignore. Сделать сегодня.
3. **P1 — надёжность плагинов**: таймауты на все fetch (tg-user-tools, jina-core). Это защита от «зависшего агента».
4. **P2 — сеть**: miniapp увести с 0.0.0.0 за loopback/nginx-TLS.
5. **P3 — чистота**: удалить мёртвый код (icloud_calendar, orchestrator, flight_watch, backup-crontab), унифицировать venv, requirements.txt.
6. **Экономия**: memorySearch на Jina-embeddings (бесплатно в квоте) вместо платного OpenRouter.
7. **Наблюдаемость**: актуализировать healthcheck (svc — systemd!), ротация логов, проверка git-чистоты.
8. **Не хватает артефактов для полного аудита**: policy/конфиг exec-безопасности OpenClaw, история промптов, содержимое .clawpatch — по ним оценка частичная.
9. **Общий вывод**: архитектура — 6/10, к продакшену пригодна, но техдолг (git-секреты, таймауты, дубли) стоит разгрести в ближайшие 2–3 дня; это quick wins, не стратегическая перестройка.
